# SECURITY.md

## 🔐 Security Policy

Thank you for helping keep this project secure.

This project is an AI-powered browser extension that acts as a bridge between supported AI providers, including DeepSeek and Google Gemini. Protecting user data, API keys, and communications is a top priority.

## Supported Versions

| Version           | Supported  |
| ----------------- | ---------- |
| Latest release    | ✅ Yes      |
| Previous releases | ⚠️ Limited |
| Older releases    | ❌ No       |

## Reporting a Vulnerability

If you discover a security vulnerability, **please do not open a public issue**.

Instead, report it privately to the project maintainer.

When reporting a vulnerability, please include:

* A description of the issue
* Affected version(s)
* Steps to reproduce
* Expected and actual behavior
* Potential impact
* Any proof of concept or suggested mitigation (if available)

We aim to acknowledge reports as quickly as possible and work on a fix before public disclosure.

## API Keys & Secrets

Never share or commit sensitive information, including:

* DeepSeek API keys
* Google Gemini API keys
* Authentication tokens
* Session cookies
* Private credentials
* Environment variables containing secrets

Store secrets securely using environment variables or a secure secret management solution.

Example:

```env
DEEPSEEK_API_KEY=your_api_key
GEMINI_API_KEY=your_api_key
```

Never commit real credentials to the repository.

## Data Privacy

The extension communicates with third-party AI providers to process user requests.

Users should understand that any data sent to external AI services is subject to the privacy policies and terms of those providers.

The project should never intentionally transmit:

* Passwords
* Private keys
* Authentication tokens
* Financial information
* Personally identifiable information (PII) unless explicitly required by the user

## Input Validation

All data received from users, websites, extensions, APIs, or AI models should be treated as **untrusted input**.

Proper validation and sanitization should always be performed before using data in:

* API requests
* HTML rendering
* JavaScript execution
* Database queries
* File operations
* Any security-sensitive process

## AI Safety

Responses generated by AI models should never be considered inherently trustworthy.

The extension should avoid automatically executing instructions generated by AI without additional validation.

User confirmation is recommended before performing actions that may affect:

* User accounts
* Browser settings
* Local files
* External services
* Sensitive data

## Least Privilege

The extension should request only the permissions necessary for its intended functionality.

Unused permissions and unnecessary API access should be removed whenever possible.

## Dependencies

Dependencies should be kept up to date.

Known vulnerable packages should be updated or replaced as soon as practical.

## Responsible Disclosure

Confirmed security issues will be addressed as quickly as possible.

Security patches will be released before detailed technical information is publicly disclosed whenever feasible.

## Disclaimer

While every effort is made to improve security, no software can be guaranteed to be completely secure.

Users should always keep the extension up to date and follow security best practices when using third-party AI services.
